Compact reference for agents working in this repo. Verify against code if anything seems stale.

## Build Commands

```bash
make build-full                # Frontend + backend (full build)
make build                     # Backend only
make build-frontend-integrate  # Frontend → public/ + pkg/embed/
make test                      # go test -v ./...
go test -v ./biz/service/git/... -run TestFunctionName  # Single test
make fmt                       # go fmt ./...
make lint                      # golangci-lint (optional, won't fail if missing)
```

**Frontend TypeScript check** (not in Makefile): `cd frontend && npx vue-tsc --noEmit`

### Build order matters

Frontend changes: `make build-frontend-integrate` **must run before** `make build`. The backend embeds `frontend/dist` via `pkg/embed/`.

### CGO is required

`CGO_ENABLED=1` — the project uses SQLite via `github.com/glebarez/sqlite` (C driver). The Makefile exports this automatically. If running `go build` directly, set it yourself.

### Dev servers

```bash
# Backend (port 12345)
./output/git-manage-service --mode=http

# Frontend dev (port 3000, proxies /api/v1 → localhost:12345)
cd frontend && npx vite --host 0.0.0.0 --port 5173
```

## Two Entry Points

- `cmd/server/main.go` — Web/RPC server (build tag `!desktop`). `--mode=all|http|rpc`.
- `main.go` — Wails desktop app (build tag `desktop`). Embeds `frontend/dist` via `//go:embed`.

Same `biz/` backend, compiled separately due to build tags.

## Architecture

```
Request → Router → Handler → Service → DAO → SQLite (GORM)
```

| Layer | Path | Edit? |
|---|---|---|
| Router | `biz/router/{module}/` | Generated by Hz — only `register.go` and `custom_routes.go` are safe |
| Handler | `biz/handler/{module}/` | Safe |
| Service | `biz/service/{module}/` | Safe |
| DAO | `biz/dal/db/` | Safe |
| DB Model | `biz/dal/model/` + `biz/model/po/` | Safe (GORM structs) |
| Proto Model | `biz/model/` (not `po/`) | **Do not edit** — generated from `idl/` |
| API DTO | `biz/model/api/` | Hand-written structs for API responses, safe to edit |

### Hertz route registration

Generated routers are called in `biz/router/register.go` via `GeneratedRegister()`. This file is hand-edited, not generated. Custom routes that don't come from proto must be registered here explicitly (e.g., `spec.RegisterCustomRoutes(h)`).

**Route ordering matters**: Hertz matches routes in registration order. A parameterized route like `/:id` registered before a static route `/presets` will swallow the static path. Always register static paths first.

## Code Generation (Hz)

```bash
hz update -idl idl/biz/repo.proto -mod github.com/yi-nology/git-manage-service --proto_path idl
```

Files with `// Code generated by hz. DO NOT EDIT.` must not be modified. This includes `biz/model/**/*.go` (proto models) and `biz/router/*/*.go` (except `register.go`).

## Frontend

Vue 3 + TypeScript + Element Plus + Vite + Monaco Editor + Pinia.

- **Path alias**: `@` → `frontend/src/`
- **API layer**: `frontend/src/api/modules/` — one file per domain
- **Request adapter**: `frontend/src/api/request.ts` — auto-unwraps `{ code: 0, data: ... }` responses, returns `data` directly
- **Types**: `frontend/src/types/`
- **Composables**: `frontend/src/composables/`
- **CSS variables**: `frontend/src/styles/theme.css`

### Backend JSON field naming

Backend API DTOs use **camelCase** JSON tags (e.g., `ruleId`, `endLine`, `quickFix`, `createdAt`). Frontend TypeScript types must match these exactly — not snake_case. This is a common source of field-mismatch bugs.

### Spec Editor component

`frontend/src/components/spec/SpecEditor.vue` is the main spec editor, embedded in `RepoDetailPage.vue` as a tab. It is self-contained (manages its own state, does not use Pinia stores for spec editing). Previous standalone components (`SpecAIChat.vue`, `ProblemsPanel.vue`, `CommitDialog.vue`, `RuleManager.vue`) have been removed.

## Style Conventions

- **Imports**: Three groups — stdlib / third-party / internal
- **Struct tags**: `gorm` → `json` → `form` → `binding` order
- **Error wrapping**: `fmt.Errorf("op: %w", err)`
- **Context keys**: Typed `contextKey` constants, never raw strings
- **Comments**: Function-level in English; inline business logic may be in Chinese
- **No comments** in code unless explicitly requested

## Key Domains

`repo`, `branch`, `commit`, `file`, `tag`, `stash`, `patch`, `sync`, `notification`, `credential`, `sshkey`, `audit`, `stats`, `spec`, `system`, `version`, `webhook`, `submodule`, `settings`, `review`, `cr`, `binding`, `provider`.

Each domain typically has: proto in `idl/biz/`, handler in `biz/handler/{domain}/`, service in `biz/service/{domain}/`, DAO in `biz/dal/db/`.

## Spec Subsystem

The spec subsystem has two separate lint implementations:

1. **Rule-based lint** (`biz/service/lint/lint_service.go`) — reads rules from DB via `LintRuleDAO`, fast, real-time
2. **AI lint** (`biz/service/lint/ai_lint_service.go`) — calls LLM for semantic analysis, slower
3. **Legacy validation** (`biz/service/spec/spec_service.go:ValidateSpec`) — old hardcoded rules, still used by `/spec/validate` and `/spec/rules` endpoints

The `/spec/lint` handler supports `mode` parameter: `rule_only` (default), `rule_and_ai`, `ai_only`.

### Spec API routes

- Generated routes in `biz/router/spec/spec.go`: `/spec/tree`, `/spec/content`, `/spec/save`, `/spec/lint`, `/spec/rules`, `/spec/validate`, `/spec/commit/:path`
- Custom routes in `biz/router/spec/custom_routes.go`: `/spec/ai-assist`, `/spec/ai-fix`
- Both registered via `register.go` calling `spec.Register(h)` then `spec.RegisterCustomRoutes(h)`

### AI Assist modes

The `/spec/ai-assist` endpoint accepts `action` field:
- `chat` — general Q&A, returns text response
- `complete` / `generate` — returns modified spec + `apply_content` field
- `agent` — dedicated prompt that outputs only modified file, returns `apply_content` with empty `result`

## LLM Provider Resolution

`HasDefaultProvider()` and `GetDefaultProvider()` check config.yaml first, then fall back to DB (providers added via the Settings UI are stored in DB, not config.yaml). Both sources must be checked.

## File Browser modes

The `/file/tree` endpoint supports `ref=worktree` to read from the filesystem instead of git tree. This shows untracked/new files. Regular mode reads from git HEAD and only shows committed files. The `/file/blob` endpoint also supports `ref=worktree` to read file contents from disk.

## Gotchas

- `.gitignore` excludes `pkg/embed/`, `public/`, `build/`, `data/git_sync.db`, `docs-site/node_modules/`. Do not re-add these.
- `docs-site/` is a separate docs website with its own `node_modules` — not the main frontend.
- `biz/kitex_gen/` and `biz/kitex_info.yaml` are Kitex RPC generated code.
- Database migrations in `biz/dal/db/migration.go`.
- `frontend/src/stores/useSpecStore.ts` exists but the main SpecEditor.vue does NOT use it — the editor is self-contained.
- The `.vite/` directory at repo root is a Vite cache, already gitignored.
